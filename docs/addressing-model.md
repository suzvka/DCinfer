# ADR：寻址模型（单栈）

- **状态**：已定案（0.4.0 后收敛，随下一版本发布）
- **决策**：运行时寻址唯一按 `(nodeName, portName)` 复合坐标；`alias` 是序列化/内省元数据，不参与运行时寻址
- **取代**：0.3.0 的别名寻址路径与 0.4.0 的"仅按公共别名寻址"中间方案

## 决策内容

运行时数据注入与取用（`feedInput` / `takeOutput` / `takeOutputTensor` /
`hasOutput` / `submit` 声明）唯一按 `(nodeName, portName)` 复合坐标寻址：

- **坐标唯一可判定**：不存在"这个名字属于哪个命名空间"的判断；
- **无名称解析、无回退**：查不到即报错（NodeNotFound / FeedFailed 等），无隐式行为；
- `bindInput` / `bindOutput` 的 alias 是图级签名的序列化/内省元数据（随冻结快照
  固化），供 DCIr 序列化、`submitBound` 声明推导与内省使用。

## 动机

0.3.0 引入"别名优先 + 唯一端口名回退"的混合寻址后，跨节点同名端口与跨绑定
歧义产生了难以解释的错误分类（`FeedFailed` 歧义分支），"别名空间还是坐标空间"
的心智负担持续存在。单栈以"坐标唯一"换取确定性与最小 API 面积；代价是
"接口名与结构名合一"——由图文件的版本化与宿主的内省驱动寻址对冲（见推论）。

## 被否决方案（勿恢复）

| 方案 | 来源 | 否决原因 |
|---|---|---|
| 别名寻址 + 唯一端口名回退 | 0.3.0 | 模糊匹配产生跨绑定歧义与隐式行为 |
| 单栈别名（仅按公共别名寻址） | 0.4.0 中间方案 | 未绑定端口（中间结果）没有别名，不可达 |
| 双通道（别名族 + 内部族并行 API） | 评审提案，未采纳 | 推翻单栈定案；别名解析与寻址可在宿主侧显式分离完成，无需框架承担"第二条寻址路径" |

## 推论（规范性）

1. **命名唯一性法则**：一切参与寻址的名字必须在各自命名单元内唯一。节点名
   全局唯一（GraphStore 强制）；端口名在"扁平化为接口"的时刻必须唯一——
   `exportNode` 在导出时校验并拒绝同名端口（`GraphException(DuplicatePort)`）。
   运行时复合坐标在普通拓扑下天然消歧，仅导出扁平化时刻需要此约束。
2. **宿主姿势（内省驱动寻址）**：宿主经 `inputBindings()` / `outputBindings()`
   内省取坐标并按坐标寻址，不硬编码内部名；图换版本、内部重构不影响宿主代码。
   （样板代码见 README「寻址模型（单栈）」节。）
3. **文档用语**：涉及别名处一律标注"序列化/内省元数据，不参与运行时寻址"；
   涉及寻址处一律用"(nodeName, portName) 复合坐标"。
